# PPTP 프락시 for macOS

`PPTPProxy.app`은 VM과 macOS `pppd` 없이 PPTP 서버로 프락시 연결을 시도하는 ARM64 macOS 14 이상 앱입니다. 기존 프로필과 키체인 암호를 그대로 읽습니다. 앱 아이콘도 포함했습니다.

배포본은 [GitHub Releases](https://github.com/leesop/macos_PPTP_proxy_client/releases)에서 `PPTPProxy-notarized.zip`을 받으세요. 앱은 Developer ID로 서명하고 Apple 공증 티켓을 첨부했습니다. ZIP에는 `PPTPProxy.app`, 안내문, 대응 소스 아카이브가 들어 있습니다. 압축을 푼 뒤 `PPTPProxy.app`을 실행하면 됩니다.

버전 0.5.2는 연결 해제 진행·오류를 두 화면에서 표시하고, 종료된 백엔드가 연결 중으로 남는 상태를 정리합니다. 제어 소켓 응답과 PPTP 자식 프로세스 종료 처리도 개선했습니다. 제어 소켓과 로그는 `~/Library/Application Support/PPTPProxy` 아래에 저장해 임시 디렉터리 정리로 소켓이 사라지지 않게 했습니다. 남은 연결 정리 기능은 종료 요청 뒤 프로세스가 그대로 포트를 점유하면 강제 종료합니다.

## 구성

- PPTP 제어 채널과 GRE: 번들된 오픈소스 `pptp` 1.10.0
- PPP, MS-CHAPv2, MPPE 128비트, IPCP, DNS, TCP/IP: 번들된 오픈소스 `lwIP` 2.2.1
- macOS는 VPN 인터페이스와 시스템 경로를 생성하지 않습니다. 프락시 또는 로컬 포트포워딩으로 들어온 TCP 연결만 사용자 공간 PPP 링크로 보냅니다.
- DNS 이름은 PPP에서 받은 DNS 서버를 `lwIP`가 터널 안에서 조회합니다.
- PPP/MPPE 협상이 끝나기 전의 요청은 거부합니다.

## 사용

1. `PPTPProxy.app`을 실행합니다.
2. 처음 열리는 **프로필·연결** 화면에서 기존 프로필을 고르거나 서버·아이디·VPN 암호를 새로 저장합니다. 암호는 키체인에 저장하고 다음 연결에 재사용합니다.
3. **프락시 설정** 화면에서 HTTP·SOCKS5 로컬 포트를 설정합니다. 수동 포트포워딩은 한 줄에 `로컬포트:대상호스트:대상포트` 형식으로 입력합니다. 예: `15432:10.0.0.5:5432`. **적용**을 누르면 저장됩니다.
4. **프로필·연결** 화면에서 **연결**을 누르고 macOS 관리자 권한 창을 승인합니다. GRE raw socket을 열기 위한 권한입니다. VPN 암호는 임시 FIFO를 통해 백엔드에 전달하며 명령행 인수나 설정 파일에 넣지 않습니다.
5. PPP/MPPE 연결이 성립하면 **프락시 설정** 화면으로 자동 전환됩니다. HTTP 프락시 기본 주소는 `127.0.0.1:18080`, SOCKS5 기본 주소는 `127.0.0.1:11080`입니다. 두 화면 상단에는 연결 상태, 보낸·받은 TCP 데이터 양과 연결 시간이 표시됩니다.
6. 연결 중 **프락시 설정 → 적용**을 누르면 PPTP 연결을 유지한 채 리스너를 바꿉니다. 변경된 포트와 포워딩 대상은 새로 들어오는 TCP 연결부터 적용됩니다. 새 포트가 이미 사용 중이면 기존 설정이 유지되고 오류가 표시됩니다.
7. Safari에는 macOS **시스템 설정 → 네트워크 → 현재 연결 → 세부사항 → 프락시**에서 **웹 프락시(HTTP)**와 **보안 웹 프락시(HTTPS)**의 서버를 `127.0.0.1`, 포트를 HTTP 프락시 포트로 설정합니다. 시스템 프락시를 따르는 다른 앱에도 이 설정이 적용될 수 있습니다. 개별 앱이 프락시 주소를 직접 지정할 수 있으면 그 앱에만 설정할 수 있습니다.
8. 수동 포트포워딩은 이 Mac의 `127.0.0.1:로컬포트`로 접속합니다. 목적지 `호스트:포트`는 PPTP 안에서 연결합니다. 현재 포워딩은 TCP만 지원합니다.
9. 두 화면 공통의 **연결 해제**는 로컬 제어 소켓으로 처리해 관리자 암호를 다시 요구하지 않습니다. 진행 상태와 오류는 두 화면에서 바로 보입니다. 백엔드가 이미 종료됐다면 남은 연결 표시를 자동으로 정리합니다. 제어 소켓이 사라졌지만 백엔드가 남아 포트를 점유한다면 **프로필·연결 → 남은 연결 정리**를 누르세요. 이 복구 작업은 해당 앱 실행 파일인지 확인한 뒤 관리자 권한으로 종료합니다. 앱을 종료하거나 마지막 창을 닫을 때 연결 해제 확인 창이 나타납니다. **로그 보기/접기**는 프로필·연결 화면에 있습니다.

## 확인된 범위와 제약

- ARM64에서 앱과 백엔드가 빌드됐고 코드 서명 검증을 통과했습니다. 로컬 HTTP·SOCKS5·포트포워딩 리스너, PPP 미연결 시 요청 차단, 연결 중 설정 변경과 포트 충돌 시 기존 설정 유지, 로컬 연결 해제를 시험했습니다.
- 실제 서버와 PPP/MPPE 연결 상태를 확인했습니다. 사용자는 프락시를 통한 연결 동작을 확인했고, 버전 0.5.2에서 실제 연결 후 **연결 해제**를 눌러 앱이 연결 안 됨 상태로 돌아가고 HTTP·SOCKS5 포트가 닫히는 것을 확인했습니다.
- 프락시 포트와 포워딩 포트는 IPv4 루프백 `127.0.0.1`에만 열립니다. 일반 시스템 전체 VPN, UDP 포워딩, IPv6, HTTPS 프락시 서버 자체의 TLS 종단은 제공하지 않습니다. `HTTPS` 사이트는 HTTP 프락시의 `CONNECT`로 전달됩니다.
- 관리자 권한은 연결 시작 때마다 macOS가 요구할 수 있습니다. 백엔드는 raw GRE socket을 사용하므로 권한 없이 연결할 수 없습니다.
- PPTP와 MS-CHAPv2/MPPE는 오래된 보안 기술입니다. 서버가 PPTP만 제공하는 조건에서 사용하세요.

## 소스 및 라이선스

이 저장소에 앱/백엔드 소스와 빌드에 사용한 오픈소스 소스를 공개했습니다. 같은 릴리스의 `PPTPProxy-source.tar.gz`도 해당 빌드의 소스 묶음입니다. Apple Silicon macOS 14 이상에서 Xcode Command Line Tools와 CMake를 설치한 뒤 `./build.command`로 로컬 빌드를 재현할 수 있습니다. 이 명령은 기본적으로 로컬 임시 서명을 사용합니다.

- `pptp` 1.10.0: [PPTP Client](https://pptpclient.sourceforge.net/), GPL-2.0-or-later. 원본 소스는 `pptp-1.10.0.tar.gz`, 라이선스 전문은 아카이브의 `COPYING`과 앱 `Contents/Resources/PPTP-COPYING`에 있습니다.
- `lwIP` 2.2.1: [lwIP](https://github.com/lwip-tcpip/lwip/tree/STABLE-2_2_1_RELEASE), BSD-3-Clause. 소스는 `lwip/`, 저작권·라이선스 고지는 `lwip/COPYING`과 앱 `Contents/Resources/lwIP-COPYING`에 있습니다.

GPL 대상인 `pptp` 실행 파일과 같은 릴리스에 대응 소스를 제공하며, 바이너리 배포와 동일하게 누구나 다운로드할 수 있습니다. 이 저장소의 자체 작성 코드에 대한 별도의 오픈소스 라이선스는 지정하지 않았습니다.
